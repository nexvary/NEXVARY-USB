# تسليم 0.10.0 — Virtual SIM Reader

الأساس: USB `75a748a17a40b516743dd3ac3942982ca1ed362e` (0.9.1، CI ناجح
38029443122)، وWiFi-Call `e3aaacd5991a931179ae5e899c3f6a9211772684`
(الفحوص الأربعة الأخيرة ناجحة). لم نبدأ من جديد أو نعد إلى إصدار قديم.

## التنفيذ

- محرك CSIM/TPDU، parsing صارم، متابعة GET RESPONSE وتحديد مهلات وفصل
  session غير مؤكدة. اكتشاف EF_DIR وUSIM/ISIM ثم اختيار ADF الفعلي.
- خدمة vpcd محلية فعلية للقراءة فقط؛ ATR نقل افتراضي وإعادة تهيئة جلسة
  بموافقة واضحة. خطأ النقل يزيل الاتصال بدل اختلاق استجابة بطاقة ناجحة.
- مسار AKA مباشر عبر CSIM، اختيار صريح في private config دون اعتماد إلزامي
  على CCHO/CGLA. تحقق من AID الموجود فعليًا قبل إرسال التحدي.
- عميل WiFi-Call الحالي يعمل مع الجسر؛ أضيف مستورد دليل قارئ لا يمنح صلاحيات.
- صفحة قارئ SIM جديدة، تشخيص ميداني موحد، start/stop لخدمة حقيقية ودليل
  العربية. صفحة النتائج المستقلة وPNG الكامل وJSON/CSV محفوظة.
- حزمة Linux headless مصدرية، إصدار Windows portable وInno Setup عبر CI.

## الاختبارات والأدلة

الاختبارات المحلية تشمل AT/APDU/EF_DIR/ADF والرفض والمهلات، vpcd عبر TCP
فعلي، الإزالة وإعادة التشغيل بموافقة، وmTLS فعلي بين المستودعين مع AKA
اصطناعي. فحوص Qt تفتح الصفحات وتختبر الرجوع وقابلية الوصول للأزرار وأحجام
الشاشات وDPI، وصورة النتائج الكاملة. صور الواجهة من التطبيق الجاري فعليًا؛
الأجهزة وبيانات الشريحة محاكاة معلنة.

بيئة Work تمنع إنشاء Unix sockets، لذا تعذر تشغيل pcscd محليًا. يضيف CI
اختبارًا مستقلًا يستخدم pcsc-lite وvsmartcard-vpcd فعليين وعميل SCard خارجيًا
مع مودم اصطناعي: enumeration، SELECT MF، EF_DIR، GET RESPONSE، READ RECORD
وإزالة البطاقة. التقرير الناتج `virtual-pcsc-evidence.json` يحدد الفرق بوضوح.
راجع نتيجة تشغيل CI المرتبط بالتغييرات قبل وصف هذا الاختبار بأنه ناجح.

## الحدود والمتبقي

- لا فلاشة مادية داخل Work: K3770 EF_DIR وADF وAKA لم تثبت ميدانيًا بعد.
- Windows PC/SC driver غير مضمن وغير مثبت/موقّع/مختبر؛ Direct CSIM يعمل
  دون هذا التعريف. تشغيل خدمة vpcd لا يثبت ظهور قارئ Windows.
- PC/SC read-only لا يدعم strongSwan EAP-AKA مباشرة؛ المصادقة عبر broker
  مستقل مقيد. إعداد strongSwan وإثبات ePDG/IMS والمكالمات يحتاجان المشغل.
- ATR الحقيقي، reset كهربائي، T=1، extended APDU وإدارة logical channels
  عامة ليست مكافئة للقارئ المادي. backend logical الموجود يبقى مستقلًا.
- الوثيقة المباشرة لـOsmocom VoWiFi حجبها anti-bot؛ المعمارية راجعت من
  تنفيذ GSM-SIP Bridge مع التصريح بهذا القيد.
- صور/CI ليست إثباتًا على شريحة المستخدم. لا نسخة كاملة مكافئة لـOMNIKEY.
- لم يتم تغيير خادم المستخدم أو Outline أو الخدمات أو قواعد الشبكة.
- لا PDF جديدًا في هذا الإصدار؛ PNG/JSON/CSV هي الصيغ العاملة المحفوظة.
- لا تحديث Android في هذه الدفعة: يستخدم عميل WiFi-Call مساره الحالي؛
  لم يُبن APK جديد بسبب عدم وجود تغيير فيه. احتياجات Android/VoWiFi
  الميدانية تبقى ضمن المراحل التالية، دون اختلاق Carrier Permissions.
