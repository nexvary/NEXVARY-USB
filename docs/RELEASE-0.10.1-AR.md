# USB Studio 0.10.1 — أدوات الإثبات الميداني وحدود الموافقة

استكمال HEAD السابق 1a3318592c030c23b4c025a1628393617815f51f؛ لم يحدث رجوع أو إنشاء مستودع.

## التغييرات

- تقرير Direct CSIM الواحد يضيف المنفذ المختار، VID/PID من الجرد الحالي، حالة SIM قبل SELECT، FCP الحقيقي وأبعاد EF_DIR والسجلات المقروءة وAID واختيار ADF. عدم الجاهزية يمنع APDU؛ لا PIN/PUK أو ملفات مشتركين أو كتابة.
- انتهاء الموافقة أثناء التحقق أو APDU يمنع نشر الرد المتأخر ويغلق البطاقة الافتراضية. إعادة تشغيل كائن الخدمة تحتاج موافقة جديدة؛ GUI ينشئ جلسة جديدة بعد التأكيد.
- كلا عميلَي mTLS يمنعان التحدي المكرر، ويوقفان الجلسة بعد فشل طلب ربما وصل إلى البطاقة. CSIM backend يلغي التفويض بعد خطأ العملية بدل فتح جلسة جديدة تلقائيًا.
- عميل خارجي جديد `scripts/check_field_pcsc.py` يستخدم WinSCard/pcsc-lite فعليًا، ويفصل تعداد القارئ والاتصال وSELECT وGET RESPONSE وREAD RECORD واختيار ADF. لا تثبيت تعريفات أو إعادة تشغيل خدمات.
- تحضير مصدر Windows BixVReader المثبت، مع قارئ واحد يتصل بـ127.0.0.1 بدل استماع الشبكة. هذا تحضير مصدر وليس تعريفًا مبنيًا أو موقّعًا أو مثبتًا.
- محول strongSwan اختباري في WiFi-Call يطابق get_quintuplet/resync ويستهلك AUTS مرة واحدة دون AUTH ثانٍ. اختباره عبر mTLS وبطاقة اصطناعية لا يثبت تحميل native plugin داخل charon أو IKE/ePDG.

## الاستخدام الميداني

أولًا: اختر الفلاشة في Windows، افتح «قارئ SIM الافتراضي»، ثم «تشخيص شامل واحد»، واحفظ PNG الكامل أو JSON. هذه الخطوة تعمل دون تعريف PC/SC.

ثانيًا، بعد تجهيز قارئ PC/SC محلي مناسب ومراجعته، شغّل خدمة القارئ بالموافقة وحدود ATR/reset الموضحة في الدليل. في نافذة مستقلة على جهاز الفلاشة:

```bash
python scripts/check_field_pcsc.py --consent --export field-pcsc.json
```

الأداة تختار قارئ NEXVARY الوحيد فقط. مع عدة قارئات مرّر `--reader` بالاسم المعروض. لا ترسل أوامر لقارئ عشوائي. الخطأ 8010001D يعني خدمة PC/SC غير متاحة، ولا يعني فشل المودم أو الفيرموير. لا يُعاد تشغيل pcscd أو SCardSvr تلقائيًا. قارئ Windows غير مثبت لن يُكتشف بمجرد تشغيل vpcd.

العميل الخارجي يحتاج مكتبة USB المصدرية لقراءة FCP؛ حزمة Linux تضمها. هذه الأداة CLI مصدرية وليست زر تشغيل تعريف داخل EXE. توجد مهلة للعملية في اختبار CI؛ الاستدعاء اليدوي يعتمد أيضًا على مهلات النظام وخدمة القارئ المحلية.

## ما لم يثبت

الجهاز الفعلي الوحيد يبقى K3770 / 21.023.04.00.11 / 12D1:14C9. لا جهاز USB متاح في بيئة التنفيذ؛ لا EF_DIR/ADF/AKA جديدة على شريحته، ولا PC/SC ميداني، ولا ePDG/IMS/مكالمات أو صوت. النتائج الاصطناعية تحمل وصف المحاكاة.

Windows: مصدر UMDF1 الخارجي يحتاج WDK مناسبًا، بناء x64، ومراجعة lifecycle ثم توقيعًا مقبولًا وتثبيتًا واختبار SCard منفصلين. لا WDK أو شهادة توقيع في هذه البيئة؛ لم نثبت بناء التعريف. لا تعطيل Secure Boot أو حماية Windows أو حقن شهادة اختبار كمسار عادي.

strongSwan: يحتاج native plugin يربط callbacks الخاصة بـlibsimaka بالمحول المقيد، ومراجعة عزل العملية والذاكرة والتفويض. الكود الاختباري ليس إضافة قابلة للتحميل. لا SQL لتخزين CK/IK أو RES ولا تمرير أسرار في argv.

لا تغيير لخادم المستخدم أو Outline أو firewall أو المنافذ القائمة. ATR 3B00 للنقل فقط وreset يعيد اختيار الجلسة دون reset كهربائي. راجع نتائج CI المرتبطة بالـHEAD قبل وصف حزم Windows أو PC/SC الخارجي بأنها اجتازت التحقق.
