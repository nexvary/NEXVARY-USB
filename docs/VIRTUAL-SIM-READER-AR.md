# دليل NEXVARY Virtual SIM Reader — 0.10.0

الفلاشة هي وسيط الوصول الأساسي إلى الشريحة؛ لا يلزم شراء OMNIKEY أو قارئ
PC/SC مادي. الوصول إلى USIM يعتمد على الشريحة والمودم والفيرموير، ولا تثبته
عبارة Unlocked أو Voice Enabled. النسخة ليست مكافئًا كاملًا لقارئ ISO 7816.

## ما يعمل برمجيًا

- Direct CSIM: جلسة AT حصرية، تأطير T=0، تفسير SW، متابعة 61/9F، تصحيح
  طول GET RESPONSE وREAD RECORD عند 6C مرة واحدة، دون إعادة AUTHENTICATE.
- EF_DIR عبر CSIM: SELECT MF ثم EF_DIR وقراءة وصف FCP والسجلات حتى ثمانية
  واستخراج AID حقيقي. لا قراءة سجلات بطول تخميني، ولا استبدال AID بآخر.
- اختيار USIM/ISIM المكتشف. لا PIN أو PUK أو تغيير ملفات الشريحة.
- Virtual PC/SC: بروتوكول vpcd الحقيقي، خدمة محلية بوضع reversed، قراءة MF
  ودليل التطبيقات واختيار ADF المكتشف، والتوقف/الإزالة عند خطأ النقل.
- AKA الداخلي: اختيار صريح بين logical وcsim، منفصل عن واجهة PC/SC العامة؛
  مصادقة mTLS مثبتة بالشهادات، رمز scoped وموافقة حتى 300 ثانية و32 تحديًا.

ATR المودم الحقيقي غير متاح عبر هذا المسار. القارئ يقدم **ATR نقل افتراضيًا
3B00** فقط بعد موافقتك. Power/Reset يعيدان تهيئة جلسة SELECT فقط ولا يقطعان
طاقة الشريحة أو يعيدان ضبطها كهربائيًا. هذا حد توافق فعلي؛ التطبيقات التي
تحتاج ATR الحقيقي أو reset كهربائي أو logical channels غير متاحة عبر هذا
القارئ. لا يدعم PC/SC في هذه النسخة AUTH أو PIN أو ملفات المشتركين أو الكتابة.
التطبيقات الخارجية التي تحتاج وظائف أوسع (ومنها استخدام strongSwan الكامل
عبر eap-sim-pcsc) ليست مدعومة بعد؛ استخدم جسر AKA المقيد المستقل.

## Windows: أداة واحدة للتشخيص الميداني

1. افتح USB Studio واختر **الجهاز الفعلي** في قسم الأجهزة.
2. افتح **قارئ SIM الافتراضي** ثم **تشخيص شامل واحد** ووافق على القراءة.
3. النتائج تفتح في الصفحة المستقلة؛ احفظ PNG كاملًا أو JSON/CSV من التقارير.
4. لا تختبر CCHO/CGLA أو أوامر مصادقة عشوائيًا. الأداة تركز على CSIM/EF_DIR/ADF.
5. زر التشغيل ينشئ خدمة محلية فعلية، لكنه لا يثبت تثبيت تعريف PC/SC.

من المصدر أو CLI:

```powershell
python -m pip install -r requirements.txt
python -m nexvary_usim_lab reader-diagnose --consent --export field-reader.json
```

يختار المنفذ تلقائيًا عند وجود مجموعة واحدة؛ مع عدة أجهزة اختر الجهاز في GUI
أو مرر `--port` للمنفذ المكتشف الحالي، دون تثبيته في الشفرة.

## Linux: تشغيل القارئ الافتراضي

هذه الأوامر للكمبيوتر المتصل بالفلاشة، وليست افتراضًا أن VPS يحمل USB.
راجع أي pcscd وقارئات وخدمات قائمة قبل إضافة إعدادك؛ لا توقف خدمات الخادم.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-reader.txt
sudo apt-get install pcscd vsmartcard-vpcd
.venv/bin/python -m nexvary_usim_lab virtual-reader --consent \
  --allow-emulated-atr --allow-session-reset --vpcd-port 35963
```

اضبط ملف قارئ vpcd **واحدًا** في `reader.conf.d` بحيث يكون:

```text
FRIENDLYNAME "NEXVARY Virtual SIM Reader"
DEVICENAME 127.0.0.1:35963
LIBPATH /usr/lib/pcsc/drivers/serial/libifdvpcd.so
CHANNELID 35963
```

تعريف Ubuntu vpcd 0.8 ينهار في وضع الاتصال العكسي عند إعادة الاتصال بموضع فارغ. استخدم المصدر المثبت الذي اختبره CI:

```bash
sudo apt install git gcc pkg-config libpcsclite-dev pcscd
bash scripts/linux/build-vpcd-reviewed.sh nexvary-vpcd-dependency
realpath nexvary-vpcd-dependency/libifdvpcd-nexvary-reviewed.so
```

ضع المسار المطلق الناتج في LIBPATH. السكربت يبني التعريف فقط ولا يثبته أو يوقف خدمات. يحتفظ بالمصدر والترخيص GPL-3.0-or-later بجانب الملف؛ حزمة NEXVARY لا تضم ثنائي التعريف. لا تستخدم `/dev/null:35963`: وضع vpcd الافتراضي
يمكن أن يستمع على جميع واجهات الشبكة؛ الإعداد أعلاه يجعل التعريف **عميلًا**
إلى خدمة NEXVARY التي تستمع حصريًا على loopback. لا تفتح منافذ للإنترنت.
vpcd القياسي يعرض منفذين للقارئ؛ الخدمة تحجز 35963 و35964 محليًا.
المنفذ الثاني يعلن عدم وجود بطاقة عبر ATR فارغ، ولا يمثل شريحة ثانية.
تفعيل ملف القارئ يحتاج إعادة تحميل pcscd بطريقة مناسبة للخدمات الموجودة؛
الحزمة لا تعيد تشغيله تلقائيًا. شغّل NEXVARY أولًا ثم قارئ vpcd. إذا حاول
vpcd الاتصال قبل NEXVARY، قد يلزم إعادة تحميل القارئ بعد بدء الجلسة.
تثبيت الحزم قد ينشئ إعداد vpcd الافتراضي: افحصه واستبدل الإعداد الخاص
بالقارئ الافتراضي قبل تشغيله؛ لا تمس قارئات أخرى. جلسة الموافقة خمس دقائق.

تحقق من تعداد القارئ باستخدام `pcsc_scan` أو التطبيق الخارجي. إرسال
`00 A4 00 0C 02 3F 00` يجب أن يعيد **رد الشريحة الحقيقي**. توقف البرنامج
أو نزع الفلاشة يزيل الجلسة الافتراضية. إعادة التوصيل تحتاج تشغيلًا وموافقة
جديدين؛ لا إعادة إرسال تلقائية أو إعادة استخدام نتائج قديمة.

Linux PC/SC يسمح لتطبيقات محلية مسموح لها بالتواصل مع الخدمة. هذا الجسر
مخصص لجهاز محلي موثوق؛ ليس API متعدد المستخدمين. العمليات المتاحة مقيدة
بالقراءة مهما كانت صلاحيات العميل، والمصادقة غير متاحة عبر منفذ vpcd.

## Windows PC/SC

خدمة vpcd wire نفسها تعمل على Windows، لكن قارئًا يراه SCardListReaders
يحتاج تعريفًا افتراضيًا مناسبًا مثبتًا. لم نضمّن تعريف kernel أو نثبت توقيعًا
ولم نعطل Secure Boot. بعض برامج vsmartcard Windows تستخدم بنية مختلفة عن
IFD على Linux؛ لا تفترض أن مجرد تشغيل الخدمة يُنشئ قارئ Windows. المسار
المتاح دون ذلك هو Direct CSIM. ملف EXE ليس تعريف قارئ PC/SC.

## WiFi-Call

الحفاظ على الجسر الحالي مع اختيار `"transport": "csim"` اختياريًا داخل
ملف session الخاص يجعل CCHO/CGLA غير إلزاميين لمسار AKA. لا تنتقل تلقائيًا
من logical بعد مهلة، لأن نتيجة تنفيذ التحدي قد تكون غير محسومة.

```bash
python -m nexvary_usim_lab bridge --config /private/session.json --consent
```

ملف config بصلاحية 0600/ACL مالك فقط، وشهادات provisioned مستقلة، device_key
ورمز قصير العمر وAID مكتشف. لا ملفات مفاتيح حقيقية في التقرير أو سطر الأمر.
الـVPS يستخدم عميل USB الحالي عبر نفق خاص ومُعد مسبقًا وشهادات mTLS؛ القارئ
والشريحة يبقيان على الكمبيوتر المحلي. لا إعداد نفق أو Outline أو gateway
تلقائيًا. لا تخزين Ki/OPc أو استخراجها. CK/IK/RES لازمة للعملية ومؤقتة؛
Python لا يضمن محو كل النسخ من الذاكرة، فلا نصف التنفيذ بأنه ذاكرة zeroized.

## معنى النتائج

SIM READY ≠ نقل APDU ناجح ≠ EF_DIR مقروء ≠ USIM مختار ≠ AKA ≠ ePDG ≠ IMS ≠ مكالمة.
تقارير JSON سياق غير موثوق ولا تمنح صلاحيات أو تشغل Gateway. دعم K3770
الميداني السابق يثبت AT وICCID وSELECT MF فقط؛ EF_DIR وAKA في النسخة الحالية
يحتاجان تشغيل الفلاشة الفعلية. لا تستنتج قيد firmware دائمًا من مهلة واحدة.
