# NEXVARY USB Studio 0.8.2 — تكامل أدلة WiFi-Call

بُني فوق main عند `ed63b2c911dc52ae31da10ea6155f97f687f0799`، بعد دمج
تصدير القدرات في الواجهة وCLI. جميع وظائف SIM/SMS/الشبكة/eSIM Manager
ومقارنة المنافذ والجسر الآمن السابقة محفوظة. الأيقونة الحالية محفوظة.

## التغيير

من **التقارير → دليل قدرات WiFi-Call** احفظ JSON مستقلًا يفصل اتصال AT
وحالة SIM واختبار APDU عن USIM AKA وePDG وIMS ودعم الصوت والمكالمات
الواردة والصادرة والصوت ثنائي الاتجاه. التصدير من الواجهة يستخدم نتائج
الفحص الموجودة؛ لا يرسل أمرًا جديدًا إلى الجهاز أو الشريحة.

```powershell
python -m nexvary_usim_lab capabilities --port COM5 --export wifi-call-capabilities.json
```

في CLI يمكن إضافة `--consent` للاختبار الثابت SELECT MF الموجود أصلًا.
لا تُرسل AUTHENTICATE أو مكالمة أو PIN بواسطة التصدير. CLI لا يستبدل
تقريرًا موجودًا. يحتوي التقرير على حالة محاكاة واضحة ولا يتضمن رقم
الشريحة أو ICCID/IMSI/IMEI أو مفاتيح المصادقة أو ردود APDU الخام.

صيغة `nexvary.usb.capabilities.v1` تسجل المشاهدات وتبقي إذن المكالمات
وإتاحة رقم الشريحة `false`. ليست شهادة موقعة؛ تعديل JSON لا يمنح
الثقة أو التفويض. الجسر الفعلي يبقي mTLS وتثبيت شهادة الطرف والموافقة
المحددة والصلاحية القصيرة. [العقد التقني](WIFI-CALL-CAPABILITY-CONTRACT.md).

## التحقق والحدود

نجحت محليًا **136 حالة unittest**، بما فيها عدم خلط SELECT MF بـAKA،
تمييز المحاكاة، منع كشف المعرفات والحقن النصي، CLI مع/دون الموافقة،
ومنع استبدال التقرير. اجتاز التعديل `git diff --check`.

نسخة Windows والمثبت وصور Qt والتحقق من التثبيت والترقية تُبنى وتختبر
في GitHub Actions؛ هذه الوثيقة لا تدّعي نجاح تشغيل لم يكتمل بعد.
نتيجة Windows تُقرأ من Run الخاص بآخر commit وملفات الأدلة المرفقة.

جهاز المالك **فلاشة واحدة Huawei K3770**، Firmware `21.023.04.00.11`
وUSB ID مشاهده `12D1:14C9`. إشارات E153 السابقة لا تعني وجود فلاشة
مستقلة. الأدلة الميدانية السابقة ليست اختبارًا جديدًا لهذا الإصدار.
الصوت وAKA الفعليان وIMS/ePDG والمكالمات الخلوية لا تزال غير مثبتة.
